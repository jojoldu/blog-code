# AI 시대에 백엔드 개발자는 무엇을 준비하면 좋을까?

AI가 발전하면서 정말 백엔드 개발자라는 포지션은 없어지는 걸까?
이런 고민을 많이 하고 있다.

주변에서 듣는 이야기들이 많으니깐 어쩔 수 없긴 한데, AI가 워낙 잘하고 있는 건 사실이다.
실제 우리 회사에서도 AI를 활용해 개발자가 아닌 분들이 코드에 기여할 수 있도록 이것저것 시도해보고 있다.

근데 실제 우리 팀의 일을 보면, 백엔드 개발자분들이 오로지 가드레일만 구축하고 있는 건 아니다.

우리 팀만 하더라도 주문과 결제, 정산 로직은 전문 백엔드 개발자분들이 다루고 있다. 틀리면 큰일 나는 영역이니깐.
이런 영역에서는 전문가가 AI를 함께 써서 더 안전하게 처리하고 생산성도 높이는 데 집중한다.

반면 덜 위험하고 언제든 롤백할 수 있는 부분에서는 좀 더 과감하게 시도하기도 한다.

그래서 SNS에서 계속 언급되는 백엔드 개발자의 역할이 사라진다는 이야기도 실제로 어떤 근거가 있는지 확인해보고 싶었다.
(개발이란 눈에 보이는 부분은 다 똑같아 보여도 내부는 완전히 다른 영역이니깐)

그래서 AI 모델을 직접 만드는 회사들의 채용공고를 찾아보게 됐다.  
  
왜 AI 모델을 만드는 회사냐하면,  
AI 시대에 있어서 모든 영역의 기업들보다 2~3년은 앞선 환경을 경험하고 있기 때문이다.  
  
OpenAI의 한 엔지니어는 토큰을 원하는 만큼 쓰면서 Codex를 실험할 수 있다고 했다.
앤트로픽에서는 외부에 공개하지 않은 프론티어급 모델도 사내 코딩과 연구에 쓰고 있다고 했다.  

이 회사들은 우리가 앞으로 겪을 개발 환경을 먼저 경험하고 있는 것 같았다. 그래서 지금 어떤 개발자를 찾는지가 궁금했다.  
  
제일 먼저 보이는건 당연하게도 FDE와 같이 AI로 인해 새롭게 등장한 직무이다.  
이 건 기사나 SNS로 이미 많이 이야기되고 있는 직무이다.  

그럼 그 외 직무 채용은 없는걸까?    
  
놀랍게도 그렇지 않았다.  
전통적인 엔지니어링 포지션이 생각보다 많았다.  
가장 대표적인 직무는 "결제와 과금을 맡길 백엔드 개발자" 를 모두 채용하고 있었다.  

OpenAl: Staff & Software Engineer, Payments & Billing, Consumer Monetization
Anthropic: Staff+ Software Engineer, Billing Platform
AWS: Software Development Engineer, Billing Data Services
Cursor: Software Engineer, Billing

OpenAI는 백엔드나 분산 시스템을 설계하고 운영해본 경험을 요구했다. 중복 요청과 동시성 문제를 어떻게 다루는지, 데이터가 틀어지거나 일부 처리가 실패했을 때 어떻게 복구할지 판단할 수 있는 사람을 찾고 있었다.

Cursor 공고에는 사용량 기반 과금 시스템을 실제로 운영해본 경험과, 고객의 잔액과 크레딧을 기록하는 원장을 구축하거나 유지보수해본 경험까지 적혀 있었다.


결제, 정산, 재고 같은 업무에서는 구현에 드는 비용뿐 아니라 잘못 처리했을 때의 손실과 복구 비용까지 따져야 한다.
AI로 코드를 빨리 만들 수 있어도, 잘못 청구한 돈을 바로잡거나 틀어진 재고를 복구하는 일은 여전히 필요하니깐.

이런 시스템에서는 그 업무를 아는 백엔드 개발자가 AI를 활용해 설계와 운영을 맡는 편이 더 경제적일 수 있겠다는 생각이 들었다.

결제와 정산 외의 채용공고도 더 찾아봤다. AI를 만드는 회사뿐 아니라, 기존 사업에 AI를 적용하는 기업들도 함께 봤다.
백엔드 개발자가 다음에 준비해볼 만한 일을 여섯 가지로 묶어봤다. 앞의 네 가지는 시스템을 설계하고 운영하는 경험을 더 쌓는 쪽이고, 뒤의 두 가지는 제품과 고객 업무까지 맡아보는 쪽이다.

1. 도메인 특화 엔지니어

결제와 정산, 예약과 재고처럼 업무 규칙이 복잡하고 잘못 처리했을 때 손실이 큰 시스템을 맡는다.

대표공고: OpenAI: Staff & Software Engineer, Payments & Billing, Consumer Monetization

작은 구독 서비스를 모의 결제로 만들고, 중복 요청이나 응답 유실이 생겨도 청구 내역과 이용 권한이 맞는지 확인해보면 좋겠다.

2. 플랫폼 엔지니어

인증과 권한, 문자와 이메일 발송, VOD처럼 여러 팀이 공통으로 사용하는 서비스와 API를 만든다. 한 팀의 요청이 몰려도 다른 팀이 계속 쓸 수 있어야 한다.

대표공고: OpenAI: Backend Software Engineer, Applied Foundations
Anthropic: Staff+ Software Engineer, Auth & Identity

앤트로픽의 인증과 권한 공고에는 대규모 백엔드나 플랫폼 운영 경험과, OAuth나 역할 기반 접근 제어를 다뤄본 경험이 적혀 있었다. 사용자가 계속 서비스를 쓰는 동안 기존 시스템을 단계적으로 바꾸고, 다른 팀이 쉽게 사용할 수 있도록 문서와 도구를 제공하는 능력도 보고 있었다.

주문 서비스와 학습 서비스가 같은 메시지 발송 API를 쓰게 만들고, 발송량 제한과 재시도, 중복 발송 방지까지 구현해볼 수 있다.

3. 대규모 데이터 처리 엔지니어

대량의 데이터를 수집하고 가공해서 서비스와 분석에 필요한 형태로 제공한다.

대표공고: OpenAI: Data Engineer
Google: Software Engineer III, Google Cloud, Dataform

OpenAI는 분산 데이터 처리와 저장 시스템을 다뤄본 경험을 요구했다. Spark 코드를 작성하고 오류와 성능 문제를 해결할 수 있어야 했고, Airflow 같은 도구로 데이터 처리 작업을 관리해본 경험도 채용 요건에 들어 있었다.

주문 이벤트로 매출을 집계하는 파이프라인을 만들고, 이벤트가 늦거나 중복돼도, 중단된 작업을 다시 실행해도 합계가 맞는지 확인해볼 수 있다.

4. AI 시스템 엔지니어

자사 서비스와 사내 업무에 LLM과 에이전트를 적용하고, 답변과 실행 결과를 평가하며 운영한다.

대표공고: Walmart: Staff, Software Engineer
Google: Web Solutions Engineer, Technology and Insights Partnership Systems, YouTube India

월마트는 분산 시스템을 만들고 운영한 경험과, AI 모델이나 LLM API를 실제 서비스에 연동해본 경험을 요구했다. 결과를 어떻게 평가할지, 지연 시간과 비용을 어떻게 관리하고 실패하면 어떻게 처리할지까지 설계할 수 있어야 했다.

작은 FAQ 챗봇과 평가 도구를 만들어, 프롬프트를 바꿀 때 답변의 품질과 응답 시간, 비용이 어떻게 달라지는지 비교해보면 좋겠다.

5. 프로덕트 엔지니어

사용자의 문제를 이해하고 화면과 서버를 함께 구현한다. 출시한 뒤 실제 사용 결과를 보면서 무엇을 바꿀지도 판단한다.

대표공고: OpenAI: Product Engineer, Full Stack - Agents
Anthropic: Senior Software Engineer, Full-stack
xAI: Member of Technical Staff - Grok Product

OpenAI의 프로덕트 엔지니어 공고는 React와 TypeScript로 화면을 만들고, 실제 서비스의 API와 데이터 모델을 설계해본 경험을 함께 요구했다. 고객의 문제가 명확하지 않은 상태에서도 무엇을 만들지 판단하고, 구현부터 출시와 개선까지 맡아본 사람을 찾고 있었다.

작은 제품을 화면과 서버까지 만들어 실제로 쓸 사람에게 주고, 그 사람의 일이 편해졌는지 물어보며 고쳐보는 것이다.

6. FDE(Forward Deployed Engineer)

고객의 업무와 기존 시스템을 파악하고, 자사 기술을 고객 환경에서 쓸 수 있도록 구현하고 배포한다. 도입한 뒤 업무에 도움이 되는지까지 함께 확인한다.

대표공고: OpenAI: Forward Deployed Engineer (FDE) - Seattle
Anthropic: Forward Deployed Engineer

앤트로픽은 LLM 서비스를 만들고 평가해 운영 환경에 배포해본 경험과 Python 개발 역량을 요구했다. 고객의 업무를 직접 파악하고, 기술적인 내용을 여러 직군이 이해할 수 있게 설명하는 능력도 채용 기준에 들어 있었다.

문의 접수와 문서 조회, 답변 초안 작성을 연결하는 도구를 만들고, 사용할 사람의 기존 시스템과 데이터, 권한에 맞춰 연동해볼 수 있다.

프로덕트 엔지니어와 FDE는 백엔드 전용 포지션은 아니지만, 백엔드 개발자가 맡는 일을 넓혀볼 수 있어 함께 넣었다.
지금 맡은 일이나 관심 있는 업무와 가까운 과제 하나부터 골라보면 좋겠다. 운영 중인 서비스가 있다면 그 서비스에서 같은 문제를 찾아보고, 설계한 이유와 실패 상황을 테스트한 결과를 기록해볼 수 있다.

각 방향의 채용공고와 필요한 경험, 과제 진행 방법은 후속 글로 소개하고, 참고할 강의도 수업 내용을 확인해 인프런 기획전으로 모아보려 한다.

공고들을 살펴보고 나니, AI가 더 발전하면 백엔드 개발자가 할 일은 없어질 거라는 생각에는 동의하기 어려웠다. AI를 적극적으로 쓰는 회사들도 어떤 업무를 이해하고, 어떤 시스템을 설계하고 운영해봤는지를 여전히 구체적으로 묻고 있었다.


그럼 이렇게 좀 더 심화된 각 직무들로 나아가려면 어떻게 해야할까?  
는 내일 다시 정리하는걸로.....
