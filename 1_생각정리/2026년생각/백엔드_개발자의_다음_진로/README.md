# 백엔드 개발자는 정말 없어질까?

AI 시대가 오면서 정말 백엔드 개발자라는 포지션은 없어지는 걸까?
FDE와 AI 엔지니어 두 직무만 남는 걸까?
이런 고민들을 많이 하고 있다.

주변에서 듣는 이야기들이 많으니깐 어쩔 수 없긴 한데, AI가 워낙 잘하고 있는 건 사실이다.
실제 우리 회사에서도 AI를 활용해 개발자가 아닌 분들이 코드에 기여할 수 있도록 이것저것 시도해보고 있다.

근데 실제 우리 팀의 일을 보면, 신규 사업이나 실험을 시도할 때도 백엔드 개발자분들이 오로지 가드레일만 구축하고 있는 건 아니다.

우리가 아직 AI 네이티브 조직으로 충분히 바뀌지 못해서 그런 걸까. 앞으로는 개발 조직도 FDE와 프로덕트 엔지니어, AI 엔지니어 위주로 바꿔야 하는 걸까.
(우리 회사는 AI SaaS가 없으니 FDE보다는 사내 AI 도입을 맡는 AX 엔지니어를 생각하게 되겠지만.)

나는 실체 없이 확산되는 부정적인 이야기를 신뢰하지 않는다. 그래서 백엔드 개발자의 역할이 사라진다는 이야기에도 실제로 어떤 근거가 있는지 확인해보고 싶었다.

2~3년 뒤에 백엔드 개발자라는 포지션이 어떻게 될지 생각할 때, 가장 먼저 확인해볼 만한 건 AI의 최첨단에 있는 회사들의 채용공고였다.

OpenAI의 엔지니어는 공식 행사에서 토큰을 원하는 만큼 쓰면서 Codex를 실험할 수 있는 환경을 설명했다. [OpenAI 엔지니어 인터뷰](https://forum.openai.com/public/videos/event-replay-inside-applied-ai-engineering-at-openai-2026-08-27)
앤트로픽도 8월 보고서에서 당시 미공개 프론티어급 모델을 사내 코딩과 연구에 활용한다고 밝혔다. [앤트로픽 보고서](https://www-cdn.anthropic.com/f61d49fa5596956a5dec75fea0e973bf6a6a8378/Redacted%20Risk%20Report%20August%202026%20.pdf)

우리가 앞으로 더 좋은 모델을 더 많이 쓸 수 있게 됐을 때의 개발 환경을, 이 회사들은 먼저 경험하고 있다고 생각했다.
그런 환경에서 어떤 업무를 개발자에게 맡기고 어떤 경험을 채용 기준으로 삼는지 살펴보면, 우리도 다음에 무엇을 준비할지 힌트를 얻을 수 있지 않을까.

그래서 그 회사들이 백엔드 엔지니어를 계속 채용하는지, 채용한다면 어떤 일을 맡기는지 확인해보기로 했다.

OpenAI와 앤트로픽은 지금 결제와 과금 백엔드 개발자를 채용하고 있다. [OpenAI 공고](https://openai.com/careers/staff-and-software-engineer-payments-and-billing-consumer-monetization-san-francisco/), [앤트로픽 공고](https://job-boards.greenhouse.io/anthropic/jobs/5146298008)

OpenAI는 사람이 직접 작성한 코드 없이 사내용 베타 제품을 만든 실험을 공개했다. 엔지니어들이 개발을 이끌고, 코드는 Codex가 작성하는 방식이었다. [OpenAI의 개발 실험](https://openai.com/index/harness-engineering/)

이런 환경에서 찾는 결제 백엔드 개발자는 중복 요청에도 두 번 청구되지 않게 만들고, 결제 업체와 내부 데이터가 달라졌을 때 원인을 찾아 복구할 수 있는 사람이었다.

결제, 정산, 재고 같은 업무에서는 구현에 드는 비용뿐 아니라 잘못 처리했을 때의 손실과 복구 비용까지 따져야 한다.
AI로 코드를 빨리 만들 수 있어도, 잘못 청구한 돈을 바로잡거나 틀어진 재고를 복구하는 일은 여전히 필요하니깐.

이런 시스템에서는 전문가가 AI를 활용해서 업무 규칙을 설계하고, 중복 요청이나 부분 실패에서도 데이터가 제대로 반영되는지 확인하며 운영까지 맡는 편이 더 경제적일 수 있겠다는 생각이 들었다.

결제와 정산 외에도 백엔드 개발자에게 어떤 일을 맡기고 있는지 더 찾아봤다. AI를 직접 만드는 회사뿐 아니라, 기존 서비스와 업무에 AI를 적용하는 회사들의 공고도 함께 봤다.

공고를 읽다 보니 기존에 하던 백엔드 개발과 이어지는 일들이 있었다. 여러 팀이 함께 쓰는 API를 만들거나 대량의 데이터를 처리하는 일도 있었고, 회사의 기존 시스템에 AI를 연결해서 업무에 쓰게 만드는 일도 있었다. 이런 업무들을 보면서 백엔드 개발자가 다음에 준비해볼 만한 일을 여섯 가지로 묶어봤다.

앞의 네 가지는 시스템을 설계하고 운영하는 경험을 더 쌓는 쪽이다. 프로덕트 엔지니어와 FDE는 화면까지 직접 만들고 제품을 개선하거나, 고객의 업무를 이해하고 필요한 기능을 구현하는 쪽이고. 백엔드 전용 포지션은 아니지만, 백엔드 개발자가 맡는 일을 넓혀볼 수 있어서 함께 넣었다.

**1. 도메인 특화 엔지니어**

결제와 정산, 예약과 재고처럼 업무 규칙이 복잡하고 잘못 처리했을 때 손실이 큰 시스템을 맡는다. 트랜잭션과 동시성, 중복 처리와 복구를 업무 규칙에 맞게 설계하는 경험이 중요하다.

작은 구독 서비스를 만들고, 같은 결제 요청이 여러 번 들어오거나 결제는 성공했는데 응답을 받지 못하는 상황을 만들어보면 좋겠다. 실제 돈을 청구하지 않는 모의 결제로, 청구 내역과 이용 권한을 어떻게 맞출지 연습해볼 수 있다.

**2. 플랫폼 엔지니어**

인증과 권한, 문자와 이메일 발송, VOD처럼 여러 팀이 공통으로 사용하는 서비스와 API를 만든다. 다른 팀이 쉽게 연동할 수 있어야 하고, 한 팀의 요청이 몰려도 다른 팀이 계속 사용할 수 있어야 한다.

주문 서비스와 학습 서비스가 같은 메시지 발송 API를 사용하게 만들어볼 수 있다. 사용팀마다 발송량을 제한하고, 실패한 요청을 재시도하면서도 같은 알림이 중복 발송되지 않도록 해보는 것이다.

**3. 대규모 데이터 처리 엔지니어**

대량의 데이터를 수집하고 가공해서 서비스와 분석에 필요한 형태로 제공한다. OpenAI에서도 사용자 이벤트를 처리하고 제품과 매출 지표의 기준 데이터를 만드는 Data Engineer를 채용한다. [OpenAI 공고](https://openai.com/careers/data-engineer-san-francisco/)

백엔드 경험에 데이터 엔지니어링을 더하는 쪽이다. 주문 이벤트를 모아 매출을 집계하는 파이프라인을 만들고, 이벤트가 늦거나 중복으로 들어와도 결과가 맞는지 확인해볼 수 있다. 처리가 중간에 멈췄을 때 다시 실행하는 과정도 연습해보면 좋겠다.

**4. AI 시스템 엔지니어**

회사 업무와 서비스에 LLM과 에이전트를 적용하고, 실제로 사용할 수 있도록 실행과 평가 시스템을 만든다. 월마트에는 사내 시스템 변경의 위험을 판단하고 검증하는 데 AI를 적용하는 소프트웨어 엔지니어 공고도 있다. [월마트 공고](https://careers.walmart.com/us/en/jobs/R-2606196)

지난번 소개했던 작은 FAQ 챗봇과 평가 시스템을 함께 만드는 프로젝트가 여기에 해당한다. 프롬프트를 바꿨을 때 잘 답하던 질문에 계속 잘 답하는지 확인하고, 답변과 실행 기록을 남기며 응답 시간과 비용까지 비교해보는 것이다.

**5. 프로덕트 엔지니어**

사용자의 문제를 이해하고 화면과 서버를 함께 구현한다. 출시한 뒤 실제 사용 결과를 보면서 무엇을 바꿀지도 판단한다.

AI 코딩 도구의 도움을 받아 프론트엔드까지 구현 범위를 넓혀보고, 작은 제품을 실제로 사용할 사람에게 제공해보면 좋겠다. 기능이 동작하는지에 더해 그 사람의 일이 편해졌는지 확인하고 수정하는 경험을 해보는 것이다.

**6. FDE(Forward Deployed Engineer)**

고객의 업무와 기존 시스템을 이해하고, 자사 기술을 고객 환경에서 사용할 수 있도록 구현하고 배포한다. 요구사항을 정리하고 기존 시스템과 연동하며, 도입한 뒤 실제 업무에 도움이 되는지까지 확인한다. [OpenAI 공고](https://openai.com/careers/forward-deployed-engineer-%28fde%29-seattle-seattle/)

연습할 때도 실제로 사용할 사람과 함께 작은 업무 하나를 골라보면 좋겠다. 문의 접수, 문서 조회, 답변 초안 작성을 연결하는 도구를 만들고, 사용할 데이터와 권한을 정한 뒤 업무에 맞게 수정해보는 식이다.

앞으로 각 방향의 채용공고와 필요한 역량, 직접 해볼 과제를 후속 글로 차례로 소개해보려고 한다.
혼자 시작하기 막막할 때 참고할 강의도 실제 수업 내용을 확인해서 인프런 기획전으로 모아보려 한다. 할인 쿠폰도 함께 준비할 계획이다.
